# WebnovelReader (iOS)

Native SwiftUI rewrite of the web reader (`site_assets/reader.js` in the
`tts-webnovel` repo) — see the chat that generated this scaffold for the
background-audio/Piper-performance rationale. Project is generated by
[XcodeGen](https://github.com/yonaskolb/XcodeGen) from `project.yml`; the
`.xcodeproj` itself is gitignored-equivalent in spirit (regenerate, don't
hand-edit) — run `xcodegen generate` after changing `project.yml` or
adding/removing files under `WebnovelReader/`.

## First-time setup

1. Install Xcode from the App Store (Command Line Tools alone aren't enough).
2. `brew install xcodegen` (already done if you're reading this after the
   scaffold was generated).
3. `xcodegen generate`, then open `WebnovelReader.xcodeproj`.
4. Select the `WebnovelReader` target → **Signing & Capabilities** → Team →
   pick your personal Apple ID ("Personal Team"). No paid enrollment needed.
5. Plug in your iPhone, select it as the run destination, hit Run. First
   launch on-device requires enabling **Developer Mode** in
   Settings → Privacy & Security (device will prompt/reboot once).
6. Free-account builds expire after **7 days** — reopen Xcode and hit Run
   again, or set up [AltStore/SideStore](https://altstore.io) for wireless
   auto-refresh.

## What's here

Talks to the one deployed server (Cloud Run service `novel-web`, GCP
project `tts-pipeline-yl`) — `SessionStore.baseURL` is hardcoded, there's
no server picker in the UI. Reuses the exact same endpoints
`site_assets/reader.js`/`download.js` do (no separate JSON API needed):
`books.json`, `books/<id>/meta.json`, `books/<id>/data/NNNN.html`,
`POST /api/tts`, all behind the same session-cookie login.

- `App/WebnovelReaderApp.swift` — sets `AVAudioSession` category to
  `.playback` at launch; paired with `UIBackgroundModes: [audio]` in
  `project.yml`, this is what lets synthesis/playback keep running with the
  screen locked (the thing the PWA can't reliably do — see
  `site_assets/reader.js:198-199`).
- `Networking/SessionStore.swift` + `Keychain.swift` — login (username/
  password only) via the same `POST /login` form the web login page uses;
  password goes to Keychain, session cookie to `HTTPCookieStorage.shared`
  (shared with `AsyncImage`'s own requests too). Re-validated on every
  launch (`restoreSession()`).
- `Networking/APIClient.swift` — the actual HTTP calls (books list, chapter
  fragments, cover images, `/api/tts`).
- `Networking/ChapterFragmentParser.swift` — turns a chapter's HTML
  fragment into a plain-text `Chapter` (strips tags, matches the entities
  `book_renderer.py`'s `html.escape()` produces).
- `TTS/` — `ReaderPlaybackController` drives sentence-by-sentence
  read-aloud (segmentation mirrors `reader.js`'s `splitSentences()`),
  `TTSVoice` matches the web picker's model values (`piper_vi`/
  `google_tts`/`vieneu`). `Audio/AudioPlaybackService.swift` wraps
  `AVAudioPlayer` + `MPRemoteCommandCenter`/`MPNowPlayingInfoCenter`
  (native equivalent of `reader.js`'s `setupMediaSession()`).
- `Download/DownloadManager.swift` — offline download (chapters + cover to
  Application Support), local-first reads.
- `Views/` — Login, Library, BookDetail (chapter list + download button),
  Reader (voice/speed picker, play/pause, prev/next chapter).

Not yet done: on-device TTS (Piper running locally, for true offline
read-aloud — right now offline only covers *reading*, not *listening*,
since `/api/tts` needs network).

## Verified

- `xcodebuild build` succeeds (Xcode 26.3, Swift 6).
- Login, real library list, real chapter content, download, and
  play/pause-state wiring all verified via XCUITest
  (`WebnovelReaderUITests/`) — `LoginFlowUITests` against the real
  deployed server, `TTSPlaybackUITests` proves `/api/tts` playback works
  for all three voices. Neither test hardcodes credentials — see each
  file's header for how to supply them locally.
- Known simulator quirk (not an app bug, see `TTSPlaybackUITests.swift`):
  tapping into some real book rows (cover + multi-line title) doesn't
  reliably register in this Xcode/iOS Simulator combo. Real device
  behavior not yet confirmed either way.
